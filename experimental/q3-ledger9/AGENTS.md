# AGENTS.md: q3-ledger9

Instructions for agents working in this directory. Read [`README.md`](README.md) and the
repo-root [`AGENTS.md`](../../AGENTS.md) first.

## What this is

A separate Yarn project that holds Foundation acceptance tests for SOW-Q3-01 and SOW-Q3-03
on the ledger 9 stack. It is **not** an mn-examples example:
- It is not in the root workspaces.
- It is not in the CI matrix.
- It is not generated by `yarn new:example`.

The plan, the gap ids and the status for each deliverable live in
[`../q3-delivery/q3-testing-strategy.md`](../q3-delivery/q3-testing-strategy.md). Keep that
doc in step when you add or change a test, and its Notion mirror too (see
[`../q3-delivery/AGENTS.md`](../q3-delivery/AGENTS.md)).

## Rules

- **Pins are the record's.** Versions come from the Component versions table in the Q3
  deliverables record. There are two deliberate deviations, both explained in the README:
  Midnight.js `5.0.0-rc.2` and onchain-runtime `4.0.0-rc.4`. Change a pin only when the
  record changes, and update `harness/src/stack.ts` `EXPECTED` with it.
- **Never touch the root install.** Do not edit the root `package.json` or `yarn.lock`, or
  `examples/`, from here. Run `yarn stack:check` after any dependency change.
- **Compile with `compact compile +0.35.0`**, through `harness/scripts/compact.mjs`. The
  machine default stays 0.31.1 for mn-examples. The crypto contracts need
  `--feature-zkir-v3`.
- **Do not trust memory for Compact or SDK APIs.** Every identifier here was compiled and
  run. If you add one, compile and run it too. Compilation alone proves nothing.
- **Record negatives as observed.** A hostile input may be refused before the circuit runs
  (a type error), fail an assertion, throw, or return `false`. The security property to
  assert is "never accepted". Record how it was refused in the README observations table.
  Do not change a test to make an unexpected outcome pass: a surprising outcome is a
  finding.
- **Fixtures are checked off-circuit first** (`fixtures.sim.test.ts`). A new vector goes
  through `@noble/curves` before any circuit sees it.
- **Name tests with their ids.** Put gap and AC ids (`01-G5`, `03-G3`, `AC-1`) in the
  `describe` or `it` titles. `yarn report` reads coverage from the names.
- **Keep L1 cheap.** Vector contracts hold only pure circuits and are compiled with
  `--skip-zk`. Only contracts the e2e tests deploy get proving keys, at 200 MB or more per
  signature circuit.
- **Comment contracts meticulously** (repo rule). Explain the *how* and the *why*,
  especially anything a production contract must do differently.
