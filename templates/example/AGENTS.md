## Layout

- `SPEC.md`: the design card (roles, public fields, circuits and asserts,
  privacy invariants, accepted leaks). Keep it in step with the code.
- `contract/__name__.compact` (committed), `contract/index.ts`
  (+ `contract/witnesses.ts` when the contract declares witnesses).
- `src/` harness. `src/test/__name__.sim.test.ts`: in-memory tests (logic,
  every guard, the privacy invariants). `src/test/__name__.test.ts`: the
  devnet suite (the end-to-end flow).

## Run

```bash
yarn compile:fast && yarn typecheck && yarn test:sim   # seconds, no Docker
yarn validate                    # compile, env:up, wait:dust, test:local, env:down
```

Or, from the repo root, `yarn pipeline __name__ [--json]`: it runs the next
scripts and gates (spec lint, compile:fast, --derive, typecheck, test:sim,
the SPEC code checks, compile, the UI) with the devnet in the background, and
prints what to do next.

`yarn validate` exits non-zero if any step fails, and always takes the network
down. While fixing tests, `yarn validate --keep-net` leaves the network up so
the next run skips the restart. Step by step:

```bash
yarn env:up && yarn wait:dust
yarn test:local
yarn env:down
```

## Notes for agents

- A browser UI is phase 2. Once the in-memory gate passes (`yarn typecheck`,
  `yarn test:sim`, `yarn spec:lint __name__`), run `yarn new:ui __name__` from
  the repo root, or let `yarn pipeline __name__` do it, then build the use case
  into its seed files. The devnet must still pass before the UI is done. See
  `templates/ui/AGENTS.md`.

- `contract/managed/` is generated by `yarn compile` (or `yarn compile:fast`,
  without proving keys) and gitignored. The TS harness imports from it, so
  nothing type-checks until you have compiled at least once.
- After a contract change, or a change to `create__Name__PrivateState`'s
  parameters, run `yarn compile:fast` then, from the repo root,
  `yarn new:example __name__ --derive`. It refreshes the `@generated-stub`
  regions nobody has edited (new circuits, constructor parameters, witnesses,
  the initial private state in both tests) and leaves the rest alone.
- `src/wallet.ts` has `splitShieldedCoin(color, amount)`: a shielded
  self-transfer that re-nonces a coin (and makes one of an exact value) before
  you spend it into the contract.
- The circuit-id union in `src/providers.ts` is derived from the compiled
  contract (`keyof ImpureCircuits`), so it never needs editing when circuits
  change.
- Remote-network wiring is shared, not copied. `src/wallet.ts` takes an optional
  `{ fastSync }` and the test resolves its wallet with
  `resolveWallet(network, role)` from `@midnight-ntwrk/example-fast-sync`. Do not
  write a per-example seed resolver; the shared one knows every suite's role
  names and reads the repo-root `.env.<network>`. See `FAST-SYNC.md`.
