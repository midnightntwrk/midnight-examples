# Private Party Example

A private party DApp that demonstrates the privacy boundary in Midnight DApps. Guests RSVP
under a salted commitment and stay anonymous until they arrive at the party. The entry fee is
paid in NIGHT, an unshielded token, and that payment is the exact point where a guest becomes
public. The organizer stays anonymous until they claim the collected fees, when they become
public too.

It demonstrates:

- the privacy boundary in Compact and Midnight DApps
- a salted `persistentCommit` RSVP list and a DApp-specific public key for access control
- contract syntax for a NIGHT deposit and payout (`receiveUnshielded`, `sendUnshielded`)
- MidnightJS unshielded addresses and balance checks
- MidnightJS deployment step by step (run locally, prove, balance, submit, finalize)

**Tutorial:** this example is step 2 of the [learning path](../../README.md#learning-path). The
walkthrough is in [`tutorials/`](tutorials/index.mdx) and is published at
[docs.midnight.network/tutorials/private-party](https://docs.midnight.network/tutorials/private-party).

## Run it

From the repo root, install the workspace and compile every contract:

```bash
yarn install && yarn compile
```

Then, from `examples/private-party`, start the local network, wait for DUST and run the tests
(Docker must be running):

```bash
cd examples/private-party
yarn env:up
yarn wait:dust
yarn test:local
yarn env:down
```

`yarn test:local` runs both suites: `src/test/party.test.ts`, the party end to end, and
`src/test/sponsorship.test.ts`, the sponsorship flow below.

## Gasless guests: DUST fee sponsorship

Transaction fees on Midnight are paid in DUST, and DUST is generated by registered NIGHT. A
guest can hold NIGHT for the entry fee and still be unable to submit a single transaction. This
example includes a working **fee sponsorship** flow in which Alice, the organizer, pays the DUST
for a guest who has none. The guest proves and binds their own transaction. Alice can only
attach a DUST fee offer to it. She never learns the guest's secret, so she can't RSVP or check in
on their behalf.

```bash
yarn test:sponsorship
```

See the [DUST sponsorship guide](https://docs.midnight.network/guides/dust-sponsorship) and
[`docs/SPONSORSHIP.md`](docs/SPONSORSHIP.md). They cover the sequence, the `tokenKindsToBalance`
split, the security argument, and how to reuse the pattern in your own DApp.

## Deploy to Live Testnet

The party suite uses three wallets (Alice, Bob, Charlie), and the sponsorship suite adds a fourth (Dave). On the local devnet, Alice, Bob and Charlie are pre-funded genesis wallets, and Alice sends Dave NIGHT. On a live testnet you must supply and fund a distinct wallet for each role.

To run this test script on Preview or Preprod:
1. From the repo root, run `yarn preseed:cut` and then `yarn wallets:new` (in that order — see [FAST-SYNC.md](../../FAST-SYNC.md)). That mints four wallets into a repo-root `.env.<network>` and prints their addresses. Fund each manually via the network's faucet page — [Preview](https://midnight-tmnight-preview.nethermind.dev/) or [Preprod](https://midnight-tmnight-preprod.nethermind.dev/). The faucet is a human-facing web page (no programmatic drip endpoint), so the test suite assumes each seed you supply is already funded with tNIGHT. tDUST can be delegated in 1AM or Lace Carbon (coming soon). See [Environments and endpoints](https://docs.midnight.network/relnotes/network) for reference.
1. `yarn wallets:new` writes the repo-root `.env.<network>` for you; to supply your own wallets instead, copy the repo-root `.env.<network>.example`. Each role (`ALICE`, `BOB`, `CHARLIE`, `DAVE`) needs ONE of `MIDNIGHT_<NETWORK>_<ROLE>_MNEMONIC` or `MIDNIGHT_<NETWORK>_<ROLE>_SEED`. **Dave must hold tNIGHT but must NOT have DUST delegated** — the sponsorship suite asserts it. See [SPONSORSHIP.md](docs/SPONSORSHIP.md).
1. Start the proof server: `yarn proof:up`
1. Start the test: `yarn test:preview` or `yarn test:preprod` — each wallet will sync to the network, register NIGHT→DUST if needed, and the test suite will advance programmatically.
