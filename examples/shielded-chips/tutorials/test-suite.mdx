# Run the game

This part covers the TypeScript a player needs because the roulette contract never stores their
coin, then runs a full round on a local devnet.

## Prerequisites

- [The roulette contract](/tutorials/shielded-chips/roulette), in particular the escrow
  commitment in `betColor` and its reopening in `claimWinnings`.
- Docker, with the engine running.

## The player's side of a private escrow

Storing a commitment instead of a coin moves work to the client. Two pieces of the TypeScript
exist for that.

### Recovering `mt_index`

`escrowCommit` deliberately excludes `mt_index`, and the contract never stores the coin, so
nothing on chain carries it. But `claimWinnings` needs it to spend the coin. The claimant recovers
it themselves from their own bet transaction. A transaction's outputs enter the commitment tree
in order, starting at the index the indexer reports as that transaction's `zswapStartIndex`. So
the escrow's index is that start plus the escrow output's position among the transaction's
outputs. Find the position by commitment, because the wallet's change output can come first: a
contract-owned output's commitment follows from the coin and the contract address alone.

The test calls `contractCoinMtIndex` from `@midnightntwrk/mnkit-coins` for this, and writes the
full coin into private state, so the `escrowedCoin` witness can serve it later:

```typescript title="src/test/roulette.test.ts"
  /**
   * Persist the escrowed coin so claimWinnings/forfeit can reopen it.
   *
   * The contract deliberately does not store the escrowed coin, so nothing on
   * chain carries its `mt_index`. The player recovers it from their own bet
   * transaction: its zswapStartIndex plus the escrow output's position, found
   * by commitment (`contractCoinMtIndex`).
   */
  async function recordEscrow(
    providers: ShieldedChipsProviders,
    privateStateId: string,
    base: RoulettePrivateState,
    chip: ShieldedCoinArg,
    tx: TxWithOutputs,
  ): Promise<QualifiedCoin> {
    const mtIndex = await contractCoinMtIndex(config.indexer, tx, chip, rouletteAddress);
    const escrowed: QualifiedCoin = { ...chip, mt_index: mtIndex };
    await providers.privateStateProvider.set(privateStateId, rememberEscrow(base, escrowed));
    logger.info(`Escrow recorded at mt_index=${mtIndex}`);
    return escrowed;
  }
```

The core of `contractCoinMtIndex`, in
[`packages/coins/src/coins.ts`](https://github.com/midnightntwrk/midnight-examples/blob/main/packages/coins/src/coins.ts):

```typescript
const expected = ZswapOutput.newContractOwned(decodeShieldedCoinInfo(coin), 0, contractAddress).commitment;
const position = (tx.tx.guaranteedOffer?.outputs ?? []).findIndex((o) => o.commitment === expected);
// ...query the indexer for the transaction's zswapStartIndex...
return BigInt(start + position);
```

`rememberEscrow` in `contract/witnesses.ts` just replaces the placeholder coin in the private
state. Bob's bet calls `recordEscrow` with his finalized `betColor` transaction:

```typescript title="src/test/roulette.test.ts"
  it('Bob bets RED with a 100-chip coin', async () => {
    const bobPS = createRoulettePrivateState(bobSk, bobSalt);
    bobRouletteProv.privateStateProvider.setContractAddress(rouletteAddress);
    await bobRouletteProv.privateStateProvider.set(BOB_ROULETTE_PRIVATE_ID, bobPS);

    // A fresh coin, paid for from the chip coin Alice minted him. No
    // self-transfer first: the escrowed coin's nonce is new, so the issuer
    // has never seen it.
    const chip = freshCoin(chipColorHex, BET_SIZE);
    logger.info(`Bob is betting a fresh chip coin (value=${chip.value}) on RED`);

    const tx = await (submitCallTx<RouletteContract, 'betColor'>)(bobRouletteProv, {
      compiledContract: CompiledRouletteContract,
      contractAddress: rouletteAddress,
      privateStateId: BOB_ROULETTE_PRIVATE_ID,
      circuitId: 'betColor',
      args: [chip, Color.RED],
    });

    await recordEscrow(bobRouletteProv, BOB_ROULETTE_PRIVATE_ID, bobPS, chip, tx.public);

    const state = await queryRoulette();
    expect(state.betCommits.size()).toEqual(1n);
    // The bet size is public by design; the coin behind it is not.
    expect(state.betValues.lookup(state.betCommits[Symbol.iterator]().next().value![0]))
      .toEqual(BET_SIZE);
  });
```

`mt_index` is not secret: it is a public tree position. It just isn't known until the transaction
lands, which is why it stays out of the commitment and comes in through a witness.

### Fresh coins: closing the issuer's view

One party knows more than a public observer: **the chip issuer knows the precise coin it minted
you.** Same nonce, same value. If you passed that coin's nonce to `betColor`, Alice could
recompute your escrow, and from it your payout.

So don't. The `coin` argument is not one of your wallet's coins: it describes the new coin the
transaction creates for the contract. So the test makes it up with `freshCoin`, which draws a
uniform random nonce (the ledger's `createShieldedCoinInfo`):

```typescript title="src/test/roulette.test.ts"
  // Every coin passed to houseDeposit, betColor and burn is
  // `freshCoin(chipColorHex, value)`: not a wallet coin, but the NEW coin the
  // transaction creates for the contract, with a random nonce. The wallet pays
  // for it from whichever chips it selects and takes change back under fresh
  // nonces, so no split or exact-value coin is needed, and nobody (the chip
  // issuer included) has seen the nonce before.
```

Bob's wallet pays for the bet from the coin Alice minted him, and keeps any change under a new
nonce. No split or exact-value coin comes first. The privacy suite's P8 checks that the escrowed
nonce isn't the minted one, that the minted coin is spent, and that its nonce is nowhere in the
roulette contract's public state.

An earlier version did a wallet self-transfer (`splitShieldedCoin`) before every bet to get the
same effect. That costs a transaction and a wait for indexing, and passing a fresh coin makes it
unnecessary. The browser UI does the same as the test (`freshChip` in
[`ui/src/midnight/shielded-chips-api.ts`](https://github.com/midnightntwrk/midnight-examples/blob/main/examples/shielded-chips/ui/src/midnight/shielded-chips-api.ts)),
because the DApp Connector can't list a wallet's coins in the first place.

## Run the game end to end

The end-to-end test in `src/test/roulette.test.ts` plays a full round against a local devnet:

1. Alice, the house, deploys the chips contract and mints 100 chips each to herself (twice),
   Bob and Charlie.
2. She deploys roulette bound to the chip color and deposits two match coins.
3. Bob bets RED and Charlie bets BLACK, each with a fresh coin.
4. Alice reveals RED. Bob claims 2× in a single call, Charlie forfeits, and Alice sweeps the pool.
5. It then exercises both MIP-0011 burn paths, both house-only. Alice burns half a swept coin
   (transient), then mints into the treasury and burns part of it (Merkle), checking that the
   change is persisted rather than stranded.
6. Finally it proves the gate holds: Bob cannot burn a coin he owns, and cannot mint, mint to the
   treasury, or burn from it.

Make sure the Docker engine is running, then start the local devnet from `examples/shielded-chips`:

```bash
npm run env:up
npm run wait:dust     # wait until the genesis wallet has DUST to pay fees
```

Run the tests:

```bash
npm run test:local
```

This runs both suites one after the other: `roulette.test.ts`, then `privacy.test.ts`, which
checks the privacy claims against live chain state (see
[`privacy-tests.md`](https://github.com/midnightntwrk/midnight-examples/blob/main/examples/shielded-chips/privacy-tests.md)).
Tear the devnet down with `npm run env:down` when you are done.

`Bob chip balance after claimWinnings: 200` is the 2× arriving as a single merged coin, and
`after burning 50: 150` is the transient burn taking half of a swept coin back out of existence.
Proof generation dominates the runtime: the roulette suite takes about 7 minutes, and the
privacy suite about 3 more.

Vitest lists only the tests that take longer than 300 ms, so the privacy suite shows 3 of its 12
tests, because the other nine only read state. Five of the seventeen roulette tests are missing
too. They are fast rejection checks that fail before any transaction is submitted: a deposit
cannot reuse a pool key, a loser cannot claim, Bob cannot burn a coin he owns, Bob cannot mint,
mint to the treasury or burn from it, and the house cannot burn more than a coin holds.

The first of those guards the one key the contract lets a caller choose. A deposit is stored under
its own nonce, so a second coin with that nonce and a different value, which Zswap would accept as
a different coin, would overwrite the pool entry and strand the coin already there:

```typescript title="src/test/roulette.test.ts"
  it('A deposit cannot reuse a pool key, so no match coin can be overwritten', async () => {
    // Same nonce as a pool coin, different value: a different coin Zswap
    // would accept, so only the contract's guard stops it. Rejected while the
    // transaction is built, so nothing is spent.
    const [key] = [...(await queryRoulette()).houseCoins][0]!;
    await expect(
      (submitCallTx<RouletteContract, 'houseDeposit'>)(aliceRouletteProv, {
        compiledContract: CompiledRouletteContract,
        contractAddress: rouletteAddress,
        privateStateId: ALICE_ROULETTE_PRIVATE_ID,
        circuitId: 'houseDeposit',
        args: [{ nonce: key, color: chipColorBytes, value: 1n }],
      }),
    ).rejects.toThrow(/already deposited/);
    expect((await queryRoulette()).houseCoins.size()).toEqual(2n);
  });
```

The gate checks assert on the *specific* revert message, `/Only the house/` or
`/burn amount exceeds coin value/`, rather than merely that something threw:

```typescript title="src/test/roulette.test.ts"
  it('The house cannot burn more than a coin holds', async () => {
    const coin = freshCoin(chipColorHex, BET_SIZE);
    await expect(async () => {
      await (submitCallTx<ChipsContract, 'burn'>)(aliceChipsProv, {
        compiledContract: CompiledChipsContract,
        circuitId: 'burn',
        contractAddress: chipsAddress,
        privateStateId: ALICE_CHIPS_PRIVATE_ID,
        args: [coin, coin.value + 1n],
      });
    }).rejects.toThrow(/burn amount exceeds coin value/);
  });
```

That distinction matters more than it looks. A gate test written as a bare `rejects.toThrow()`
will happily pass on a typo in its own arguments and tell you nothing about the gate. (The loser's
claim check is the one bare `rejects.toThrow()`; it also asserts that Charlie's balance stays at
zero.)

### Reading the chain back

The habit worth building: don't infer what's public from the `disclose` calls, read the chain.
Every contract's state is readable from the indexer, so you can check your own privacy claims
directly. Between the reveal and the claims, the roulette state of one run looked like this:

```

chipColor      = 8487ed1df634a057d44ee84b789fb45f692e23cafb4d1a62414b6c547499b822

bets[e67e3482…]       = RED        bets[7ed8d598…]       = BLACK
betValues[e67e3482…]  = 100        betValues[7ed8d598…]  = 100

```

Two things to notice. The pseudonyms and their behavior are fully legible: who bet what, and who
won. And there is no coin nonce anywhere for a player, so there is nothing to test a candidate
wallet key against. That is the whole design in one screen: **behavior public, identity private.**

`privacy.test.ts` automates part of that check. It collects the contracts' public state and
asserts that Bob's escrowed coin nonce, his payout coin nonce, the nonce of the coin Alice minted
him and his wallet's coin public key are not in it. If you want to check more thoroughly, take
the attacker's position. For each public nonce, and each wallet key you can guess, recompute the commitment across a few generations of
nonce derivation and search the chain for it. Done against this contract, players resolve to
nothing, and the only hits are the house's own sweeps.

## Things to try

Roughly in order of how much they'll teach you:

1. **Break it on purpose.** Put a `betCoins.insertCoin(...)` back into `betColor`, re-run the
   round, then derive the payout nonce from the published escrow nonce, compute
   `commitment(payoutNonce, color, 2 × value, walletKey)` for each test wallet and search the chain
   for it. Watching a pseudonym resolve to a wallet exactly is the fastest way to internalize
   [the nonce rule](/tutorials/shielded-chips#01-the-rule-that-shapes-both-contracts). Then make
   the test pass a coin from `availableCoins` instead of `freshCoin`, and the funding wallet
   resolves too.
2. **Swap the `mergeCoin` arguments** in `claimWinnings` and re-run the same check. Nothing about
   the game changes, and the winner becomes identifiable.
3. **Hide the bet value.** Commit to `colorBet` and the value alongside the coin, and re-prove them
   on claim. This is the same commit and reveal shape as the escrow, applied twice more, and it
   removes the last public behavior.
4. **Fix the leftover rough edges** noted along the way: give `winningNumHash` a blinding witness
   separate from the identity secret, and mix `kernel.self()` into `getDappPublicKey` for
   per-deployment unlinkability.
5. **Give `forfeit` teeth.** Design an incentive that makes a losing player settle, such as a bond
   at bet time or a deadline-based fallback, without putting the escrowed coin back into public
   state.
6. **Run multiple rounds per deployment**, which will force you to think about round-scoped
   pseudonyms and clearing state between rounds.
