# AGENTS.md — lottery

**Verified against:** Compact language `0.23`, compiler `0.31.1`,
`@midnight-ntwrk/midnight-js-*` `4.1.1`, wallet SDK `1.2.0`, Node 22.

## What it teaches

- **A verifiable draw from a committed seed:** the constructor stores
  `persistentHash(seed)`; `draw` re-hashes the witness seed against it, then
  mixes it with the tickets' `entropy`. The seed is never stored or disclosed,
  only the comparison's result and the outcome.
- **`h mod n` without a `%` operator:** the first 8 bytes of the digest
  (`slice<8>`, then `as Field as Uint<64>`, a cast that can't fail) are divided
  by a `divMod` witness, and the circuit checks `q * n + r == h` *and*
  `r < n`. The sim tests show that dropping either check lets a lying witness
  pick the winner.
- **`kernel.self()` differs inside the constructor:** a key the constructor
  stores can't be bound to the contract address. The organizer key is a plain
  hash of the secret, and the player key (computed only after deployment)
  includes the address. Both are `export pure circuit`s, so clients recompute
  them (`pureCircuits.organizerKey`, `pureCircuits.playerKey`).
- **One secret, two roles:** the same `secretKey` hashed under different
  purposes gives the organizer key and the player key, so `buyTicket` can
  refuse the organizer's own secret.
- **A deadline in Compact:** there is no `now()`. `salesEnd` is a sealed Unix
  timestamp; `buyTicket` asserts `blockTimeLt(salesEnd)` and `closeSales`
  accepts `blockTimeGte(salesEnd)` (or a sell-out), checked on chain against
  the block time. Anyone may close, so the organizer, who knows the would-be
  winner at every moment, can't choose when sales stop. The sim tests set the
  block time with `sim.time`.
- **NIGHT in and out:** `receiveUnshielded` per ticket into a tracked `pot`,
  and `sendUnshielded` of the whole pot to an address the winner chooses.
- **Several identities from one wallet** in the devnet test: organizer and two
  players as separate private-state ids (the zk-loan pattern).
- **A role-aware browser UI** (`ui/`) with persistent private state, which the
  organizer needs: the draw seed must survive between deploy and draw.

## Layout

- `SPEC.md`: the design card (roles, public fields, circuits and asserts,
  privacy invariants, accepted leaks). Keep it in step with the code.
- `contract/lottery.compact` (committed), `contract/index.ts`
  (+ `contract/witnesses.ts` when the contract declares witnesses).
- `src/` harness. `src/test/lottery.sim.test.ts`: in-memory tests (logic,
  every guard, the privacy invariants). `src/test/lottery.test.ts`: the
  devnet suite (the end-to-end flow).

## Run

```bash
npm run compile:fast && npm run typecheck && npm run test:sim  # seconds, no Docker
npm run validate                                               # compile, env:up, wait:dust, test:local, env:down
```

Or, from the repo root, `npm run pipeline -- lottery [--json]`: it runs the next
scripts and gates (spec lint, compile:fast, --derive, typecheck, test:sim,
the SPEC code checks, compile, the UI) with the devnet in the background, and
prints what to do next.

`npm run validate` exits non-zero if any step fails, and always takes the network
down. While fixing tests, `npm run validate -- --keep-net` leaves the network up so
the next run skips the restart. Step by step:

```bash
npm run env:up && npm run wait:dust
npm run test:local
npm run env:down
```

## Notes for agents

- The browser UI in `ui/` was generated by `npm run new:ui lottery`
  (persistent private state). Use-case code lives only in its seed files:
  `ui/src/midnight/lottery-api.ts` (`lotteryView`, `actionError`),
  `ui/src/components/lottery-panel.tsx` and
  `ui/src/__tests__/lottery-circuits.test.ts`, which checks the panel's
  pre-checks against the real circuits. See `packages/mnkit/templates/ui/AGENTS.md`.
- The organizer is trusted: they know the seed, so they can steer the draw by
  playing under a second secret or through a friend, by leaking the seed, or
  by refusing to draw a result they dislike (there is no draw deadline or
  refund). These are documented trust assumptions (`SPEC.md` → Out of scope),
  not bugs to "fix" piecemeal. Only the choice of when sales stop was taken
  away, by `salesEnd`.

- `contract/managed/` is generated by `npm run compile` (or `npm run compile:fast`,
  without proving keys) and gitignored. The TS harness imports from it, so
  nothing type-checks until you have compiled at least once.
- After a contract change, or a change to `createLotteryPrivateState`'s
  parameters, run `npm run compile:fast` then, from the repo root,
  `npm run new:example -- lottery --derive`. It refreshes the `@generated-stub`
  regions nobody has edited (new circuits, constructor parameters, witnesses,
  the initial private state in both tests) and leaves the rest alone.
- Shielded coins in tests come from `@midnightntwrk/mnkit-coins`
  (`packages/coins/src/index.ts`). A `ShieldedCoinInfo` argument (a tip, a
  bet, a deposit: anything the circuit `receiveShielded`s) is a new coin the
  transaction creates, not one of the wallet's coins. Pass
  `freshCoin(color, value)`, which has a random nonce. The wallet pays for it
  from whichever coins it selects and makes change, so any amount works and
  no split comes first. Never build it from the wallet's `availableCoins`: that
  nonce is shared with your wallet coin and known to whoever minted it. If the
  contract keys a map by the coin's nonce, have it refuse a nonce already
  present. If it keeps the coin off chain instead (only a commitment), the
  depositor needs the coin's tree index to spend it later:
  `contractCoinMtIndex(indexer, tx.public, coin, contractAddress)`. Use `tokenColor(domain, mintingContract)` for colors, and
  `shieldedBalance` / `waitForShieldedBalance` (a received coin shows up
  seconds after the transaction is accepted). For a mint, use `recipientOf`,
  `encryptionKeys` and `mintNonce`. In a sim test, `simCoin(value, color)`
  makes a coin. `--derive` imports them when a circuit takes a coin. Don't
  copy the local helpers in older examples' tests.
- A second contract (a test-only token the tests mint from) needs no script
  edits. Add `contract/<it>.compact`: `npm run compile` and `npm run compile:fast`
  compile every contract under `contract/` (skipping modules and imported
  files). `--derive` then adds its exports to `contract/index.ts`, plus a
  provider set and a deploy test before the main one in the devnet test. A
  second contract with witnesses of its own is wired by hand.
- The circuit-id union in `src/providers.ts` is derived from the compiled
  contract (`keyof ImpureCircuits`), so it never needs editing when circuits
  change.
- Remote-network wiring is shared, not copied. `src/wallet.ts` takes an optional
  `{ fastSync }` and the test resolves its wallet with
  `resolveWallet(network, role)` from `@midnightntwrk/mnkit-wallet`. Do not
  write a per-example seed resolver; the shared one knows every suite's role
  names and reads the repo-root `.env.<network>`. See `FAST-SYNC.md`.
