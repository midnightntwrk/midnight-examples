# AGENTS.md — leaderboard

**Verified against:** Compact language `0.28`, compiler `0.36.0`,
`@midnight-ntwrk/midnight-js-*` `5.0.0`, `@midnightntwrk/wallet-sdk` `2.0.0`,
DApp Connector API `4.0.1`, Node 22.

## What it teaches

- **Structured on-chain data.** `scores: Map<Uint<64>, ScoreEntry>` keyed by an
  auto-incrementing `Counter`. Every `submitScore` call adds a new entry, as
  on an arcade cabinet.
- **Witnesses supplying private data on demand.** `localSecretKey` feeds the
  player's key into the circuit. `getCustomName` is only called on the
  `useCustomName` branch.
- **Ownership proofs.** `ownerCommitment(sk)` (a pure circuit) is stored with
  every entry. `verifyOwnership(id)` recomputes it from the witness key and
  asserts it matches, so a successful transaction proves ownership without
  revealing the key.
- **A shared API layer.** `api/index.ts` (`LeaderboardAPI`) runs in the browser
  with Lace's providers and in Node with the test harness's providers.
- **A browser DApp on a static host.** The UI gets the proof server and indexer
  from Lace (`getConfiguration()`), serves the circuit keys from its own origin,
  and reads the leaderboard from Blockfrost without a wallet. It deploys to
  Vercel with no server code.

## Privacy: what is public and what isn't

The ledger is exactly `scores` and `nextId`.

**Hidden (and checked by the privacy test):**

- Every player's secret key. Only `ownerCommitment(sk)` and, for anonymous
  entries, `persistentHash(sk)` are stored.

**Public by design (accepted leaks):**

- Scores and custom names, in the clear.
- Linkability: all entries made with one key share `ownerHash`, and anonymous
  ones also share `displayName`. The UI keeps one key per browser, so all of a
  browser's entries are linkable to each other (not to the wallet).
- `ownerCommitment` has no per-contract salt, so one key gives the same
  `ownerHash` on every deployment.
- That someone proved ownership of an entry id, and when (a `verifyOwnership`
  transaction).
- Count and timing of submissions.
- Fee payment is not analysed.

## Layout

- `contract/leaderboard.compact`: the contract. `contract/index.ts` exports it
  with `CompiledLeaderboardContract`. `contract/witnesses.ts` has the two
  witnesses, `createLeaderboardPrivateState` and `setCustomName`. Neither file
  imports `node:*`, because the UI uses both.
- `contract/managed/leaderboard/`: **committed** compiler output (keys, ZKIR,
  the JS contract and the integrity manifest), excepted from the repo-wide
  ignore rule. The Vercel build serves it through Vite's `publicDir`, so no
  compiler is needed there. The CI job recompiles and fails if it differs.
  Compiles are deterministic for the same output path.
- `api/`: `LeaderboardAPI` (`deploy`, `join`, `submitScore`, `verifyOwnership`,
  `state$`), `decodeLedger`, `deriveState` and `utils.decodeDisplayName`. It is
  part of this package (in the `tsconfig.json` include), not its own workspace.
- `src/`: the Node harness, as in private-tip-jar. `src/providers.ts` builds
  `LeaderboardProviders` and exports the absolute `zkConfigPath`.
- `src/test/leaderboard.sim.test.ts`: in-memory tests for every guard and the
  privacy invariant.
- `src/test/leaderboard.test.ts`: Alice deploys and submits under a name, Bob
  joins and submits anonymously, `state$` ranks them, Alice proves ownership,
  and Bob's ownership proofs fail.
- `ui/`: the React DApp (`@midnight-ntwrk/example-leaderboard-ui`). It was
  ported by hand from the standalone repo, not generated by `new:ui`, so it has
  no `new-ui.json` and the CI `ui` job skips it.
- `vercel.json`: Vercel settings for Root Directory `examples/leaderboard`.
- `tutorials/`: the docs tutorial, synced to midnight-docs.

## Run

```bash
npm run typecheck && npm run test:sim     # seconds, no Docker
npm run proof:up && npm run test:preview  # the network suite
cd ui && npm run build                    # the static site, in ui/dist
```

## Notes for agents

- Don't commit `contract/managed/` after `npm run compile:fast`: it leaves out
  the proving keys and the deployed site can't prove without them. Run
  `npm run compile` before committing.
- `setCustomName` sets a module-level value that the next `getCustomName` call
  reads, so `LeaderboardAPI.submitScore` sets it just before the call. Two
  concurrent submissions with different names in one process would race.
- The tutorial quotes these files in titled code blocks, and
  `scripts/check-tutorial-code.mjs` checks the quotes are verbatim. Change the
  tutorial with the code.
- The UI never reads a committed `.env` file (the repo ignores `.env.<network>`).
  Its defaults are inline: network `preprod`, the Blockfrost Preprod indexer.
